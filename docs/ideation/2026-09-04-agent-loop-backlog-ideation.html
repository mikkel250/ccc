1

Enforce the four work classes

Human-gate vs agent-executable split Conf 92% Complexity Low

Description

The plans README already states the split. Encode it so a looping agent cannot ignore it: agent-executable (eval-parse tests #38 only), operator (in-field submit bar), needs-plan (inbox scan / M8), report-only (superseded bakeoff, retired M6, parked flexible, YAML-closed todos). AGENTS.md: never glob *-pending-*; never auto-select a plan the README does not name as active; empty Active is a successful halt. Do not add ce-next or a workset JSON — the README is the workset.

Complexity dropped from Medium to Low: the board already classifies; remaining work is AGENTS invariants plus one residual.

Basis

direct: docs/plans/README.md Active = “No in-progress implementation plan”; named leftover = eval-parse tests; operator = in-field submit bar; M8 = needs plan. STRATEGY “Not working on” includes pivot commercial path and LLM-as-judge. Zero YAML status: pending in todos/.

Rationale

Yesterday this idea was “invent a taxonomy.” Today the taxonomy is the README. The remaining risk is an agent that still greps filenames or July implementation-ready stamps and manufactures a backlog.

Downsides

AGENTS.md invariants rot if the next /ce-code-review dump is not classified on arrival. Empty-Active-as-success feels like failure unless the halt message prints operator + needs-plan lanes.

Plan lifecycle and staleness Conf 88% Complexity Low

Description

Bakeoff’s status: superseded is the pattern. Ban glob-as-queue in AGENTS.md beside “never write on main.”

The README already overlays milestone status. The hole is plan-file stamps and filename globs that still look live.

Basis

direct: retire-judges KTD5: do not rewrite completed historical plans; stamp bakeoff superseded. Extract plan still: “U3 implemented on feature/smoke-runner-extract.” app/api/lib/smoke-runner.ts is on main and imported by scripts/e2e-tailor-cv.ts. 30 pending filenames, 0 pending YAML.

Downsides

Humans still see pending in paths. Overlay notes can rot; the README must stay the authority so a stale notice cannot resurrect a milestone.

Checkbox fossils are not a queue

Queue status hygiene Conf 80% Complexity Low

Description

Closed todos still contain unchecked - [ ] acceptance criteria. AGENTS.md: on closed YAML status, checkboxes are fossils. Only a verify-against-code pass (July 05 close-out method) may reopen. Prefer the Resolution block already used when target code vanished (todos/010).

Unchanged from 2026-09-04. Still the quieter false backlog after filenames.

Basis

direct: closed todos with unchecked AC; ce-work already ignores checkbox fossils in plan bodies; July 05 plan: verify frontmatter + Work Log against current code.

Rationale

Downsides
