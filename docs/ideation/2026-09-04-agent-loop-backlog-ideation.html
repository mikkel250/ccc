Grounding Context

CCC keeps outstanding work in four unlinked queues: STRATEGY.md tracks (the de facto roadmap), dated files in docs/plans/, CE review receipts in todos/, and deferrals in docs/residual-review-findings/. There is no docs/plans/README.md, no todos/README.md, and no BACKLOG or HANDOFF manifest. Session start in AGENTS.md is “most recent plan in docs/plans/”; the 14-day stale check applies only to that newest file.

Thirty of 33 todo filenames still contain pending; YAML status: pending matches zero files. Closed-status vocabulary is five synonyms (done, completed, closed, complete, cancelled). Numeric issue_ids 001–009 each collide. Several closed todos still carry unchecked acceptance boxes. The active plan is 2026-09-03-001-feat-retire-llm-judges-plan.md (implementation-ready). Older July plans (JSON curator, flexible critique-loop, smoke cover letter) remain artifact_readiness: implementation-ready while STRATEGY lists LLM-as-judge and flexible-as-commercial-path under “Not working on.” The bakeoff plan is already stamped superseded. Residuals hold one living item (eval-parse tests, GitHub #38) plus a prose settled-conflict block with no YAML status.

STRATEGY tracks are ongoing operator goals (dial strict quality, one Master CV, two fronts / one API), not shaped code stories. Curator prompt craft is already named “not a unit” on the active plan. Buried product decisions remain inside completed batch todos (for example env-snapshot semantics in todos/014). External prior art converges on the same split: tickets as the durable graph, loops as actuators, read-point verification because ~25% of ticket premises go stale, WIP=1 because review is the bottleneck, and a stale executable roadmap being worse than none.

1

Three work classes

Human-gate vs agent-executable split Conf 90% Complexity Medium

Description

Tag every live artifact as one of four classes before any loop runs: agent-executable (shaped code with acceptance an agent can check), operator (STRATEGY tracks, submit-bar reads, prompt craft), needs-product-decision (buried calls such as env-snapshot semantics), and report-only / self (settled-conflict residuals, STRATEGY “Not working on”, superseded plans). The loop may pick only the first class. Today that set is small: dedicated eval-parse tests (GitHub #38) plus whatever the active retire-judges plan still has open. Tracks stay unshaped commander’s intent; they do not become overnight PRs.

The loop is an actuator, not a backlog groomer. Unshaped tracks and deny-listed topics never become pickable work.

Basis

direct: STRATEGY in-field track is “Dial the strict prompt until… submit bar”; active plan: “Curator prompt craft — Ongoing operator work, not a unit here.” Residual remaining actionable item is eval-parse unit tests; settled-conflict heading is “report-only; do not revert.” todos/014 L1-11: “needs a product decision.” AGENTS.md: internal ambiguity → stop and escalate.

Rationale

Filename globbing currently implies ~30 open todos. YAML says zero. A loop aimed at “all outstanding items” will either invent work from those names or chew STRATEGY tracks the repo already forbade agents to guess. Classification is the difference between an overnight agent and a false-backlog generator.

Downsides

A new execution: field can itself go stale. /ce-code-review still writes todos/, so new receipts must be classified on arrival or they re-enter the glob. Operator tracks still need a human cadence; this idea does not ticketize quality work.

2

Compile-or-halt workset

Agent-loop contract Conf 88% Complexity Medium

Description

Before /ce-work writes a file, compile a pick|skip workset from YAML status: (not filenames), STRATEGY “Not working on” as a deny-list, and residual settled-conflict as skip. Rewrite the AGENTS session-start row: read STRATEGY, then only the pointed plan — date-sort is a fallback that must ask. An empty pick set is a successful tick: print operator tracks and halt. Never glob *-pending-*. Execute at most one shaped story per invocation, then Review — matching the existing Plan → Work → Review → Compound cycle rather than a while-loop over a fake queue.

The compiler fights the read path. Status synonyms and duplicate IDs stay as messy input encoding; the loop never sees them.

Basis

direct: 30 *-pending-* files, 0 status: pending; AGENTS session start = most recent plan; July 20/27/28 plans still implementation-ready against STRATEGY “Not working on” (LLM-as-judge, flexible commercial). external: Howardism control plane (tickets = graph, loops = actuators); arXiv 2604.05000 confidence halt; WIP=1 because review is the bottleneck.

Rationale

Migrating 33 filenames fights the next /ce-code-review dump. Compiling at read time is the durable fix. Empty-set-as-success is the honest product of this repo’s current YAML: if the loop cannot print “nothing executable,” it will manufacture a backlog.

Downsides

Deny-list matching from prose headings is fuzzy. A generated workset can drift if it is committed as a second source of truth — keep it ephemeral or stamp it from STRATEGY. One-story-then-stop feels slow if the user wanted an overnight drain; that drain is unsafe until classes exist (idea 1).

3

Museum plus overlay

Plan lifecycle and staleness Conf 85% Complexity Medium

Description

Treat todos/ paths and historical plan bodies as a museum: immutable IDs and protected CE artifacts (KTD5: do not rewrite completed historical implementation plans; AGENTS: never flag plans for deletion). Do not rename 30 “pending” files — cross-links still point at those paths. Split artifact_readiness (what ce-plan stamped at write time) from liveness (shipped / superseded / parked). Add a thin overlay — a Notices-to-Mariners file — that records as-of corrections (“July 05 still claims 012–014 remain pending; that is false”). Ban glob-as-queue in AGENTS.md the same way writes on main are banned.

Mariners do not reprint every chart when a buoy moves. Agents should not rewrite protected plans to stay truthful.

Basis

direct: todos/001-pending-… line 2 is status: completed; bakeoff already has status: superseded; July 20 still implementation-ready with retired judge language; retire-judges KTD5 plus “do not create docs/plans/README.md on this branch.” external: Read-Point Planning (backlog as a cache of beliefs); Shape Up circuit breaker rather than infinite re-grooming.

Rationale

A 30-file rename is a migration that breaks citations for zero open-work gain. Leaving the museum intact and overlaying liveness is the pattern the bakeoff stamp already proved, generalized.

Downsides

Humans still see pending in filenames. The overlay can rot unless the compile step (idea 2) consumes it. Liveness stamps on protected plans must be frontmatter-only so they do not fight KTD5’s “do not rewrite bodies.”

4

Residual YAML as the living queue

Unified index / control plane Conf 82% Complexity Low

Description

Give docs/residual-review-findings/*.md the same frontmatter contract todos already have (status, execution, plan, github_issue, maybe priority). Keep STRATEGY as the human roadmap; do not add a fifth README on this branch. The small residual directory becomes the only review-derived queue an agent is allowed to scan. Eval-parse tests (#38) become an execution: code row; settled-conflict blocks become status: settled-conflict / skip. New follow-ups that survive a change land here, not back in a 33-file glob.

Basis

direct: residual file has no YAML status field; remaining actionable item is dedicated eval-parse unit tests; settled-conflict is a markdown heading only. Active plan names STRATEGY as the live thesis and forbids creating docs/plans/README.md on this branch. docs/README.md map never listed todos/.

Rationale

Plans are a protected museum; todos are a closed ledger. Residuals were invented exactly as the deferral channel. Without status, a loop cannot tell “ship #38” from “do not restore judge gates.”

Downsides

One file today — schema may look like ceremony until the next review dump. STRATEGY still needs a pointer (or idea 2’s compile) so the active plan is not discovered only by filename recency. Write-path discipline: /ce-code-review must learn to emit residuals for survivors, not only todos/.

5

Checkbox fossils are not a queue

Queue status hygiene Conf 80% Complexity Low

Description

Closed todos still contain unchecked - [ ] acceptance criteria (timeout bounds, Function types, as any mocks). Encode in AGENTS.md: on status: completed|closed|done, checkboxes are fossils, not reopen signals. Only a verify-against-code pass (the July 05 close-out method) may reopen. Prefer the Resolution / Work Log block already used when target code vanished (todos/010).

Two status channels in one file. Filename drift is visible; checkbox drift is the quieter false backlog.

Basis

direct: todos/001 and todos/012 are status: completed with unchecked AC boxes; ce-work already tells agents to ignore legacy checkbox marks in plan bodies. July 05 plan: verify frontmatter + Work Log against current code before treating a todo as open.

Rationale

Even after glob-ban and liveness stamps, an agent that “finishes the unchecked boxes” will re-implement closed work. One AGENTS invariant closes that hole.

Downsides

Does not fix filename cosmetics (idea 3 on purpose). Easy to forget when the next review skill emits new todos with mixed boxes. Genuinely unmet criteria need the verify pass, not a blanket ignore.
